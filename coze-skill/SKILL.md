# 代码重构助手

## 技能概述

本技能接收一段源代码和一句重构要求，输出重构后的完整代码。核心约束是**保持原有公共接口不变**——函数名、类名、参数签名、返回值结构都不改动，只改进内部实现与可读性。

适用语言：Python、JavaScript、TypeScript、Java、Go、Rust、C、C++。

## 何时触发本技能

用户表达以下任一意图时，调用本技能：

- 「重构这段代码」「帮我重构一下」
- 「优化这个函数」「这个函数写得太啰嗦了」
- 「把这段代码改成现代写法」「换成 async/await」
- 「提取重复逻辑」「这几段代码重复了」
- 「给这段代码补上类型标注」
- 「变量名看不懂，改名」

**不要触发的情况**：

- 用户只是让你解释代码做了什么 → 直接回答即可
- 用户想找 bug 或做代码审查 → 属于审查场景，不是重构
- 用户想改功能行为 → 属于功能开发，不是重构
- 只是单个变量改名 → 直接编辑更快

## 输入格式

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | 字符串 | 是 | 待重构的源代码，不超过 20000 字符 |
| `task` | 字符串 | 是 | 重构要求，尽量具体 |
| `language` | 字符串 | 否 | `python` / `javascript` / `typescript` / `java` / `go` / `rust` / `c` / `cpp`；不填为自动判断 |

## 输出格式

```json
{
  "ok": true,
  "code": "重构后的完整代码",
  "model": "deepseek-coder",
  "language": "python",
  "elapsed_ms": 3820
}
```

失败时：

```json
{
  "ok": false,
  "error": "可读的中文错误信息",
  "error_type": "model_not_found"
}
```

## 调用示例

**用户输入**：

> 帮我重构这段代码，变量名看不懂
> ```python
> def f(a):
>     r = []
>     for i in a:
>         if i % 2 == 0:
>             r.append(i * i)
>     return r
> ```

**应当发起调用**：

```json
{
  "code": "def f(a):\n    r = []\n    for i in a:\n        if i % 2 == 0:\n            r.append(i * i)\n    return r\n",
  "task": "把函数名与变量名改为有意义的名字，补充类型标注和中文注释，保持函数行为不变",
  "language": "python"
}
```

**期望输出**：

> 重构完成。原函数 `f` 改名为 `filter_even_squares`（保留 `f` 作为别名以免破坏调用方），参数与返回值补充类型标注。核心逻辑不变：筛选偶数并返回其平方。

## 重构要求怎么写（重要）

`task` 描述的质量直接决定结果质量。请把用户的模糊表达转成具体任务：

| 用户说 | 应转为的 task |
|---|---|
| 「太乱了」 | 「统一命名规范，拆分过长的函数，补充注释说明关键逻辑」 |
| 「优化一下」 | 「消除重复代码，简化条件判断，提升可读性，保持行为等价」 |
| 「换成新写法」 | 结合代码特征具体化，例如「把回调写法改为 async/await，保留原有的错误处理分支」 |

## 异常处理

| 情况 | 给用户的提示 |
|---|---|
| `invalid_argument` | 提示需要提供代码内容和重构要求 |
| `payload_too_large` | 代码超过 20000 字符，建议按函数拆分后分次提交 |
| `model_not_found` | 提示模型未拉取，需执行 `ollama pull deepseek-coder` |
| `ollama_unreachable` | 提示 Ollama 服务未启动，检查服务地址配置 |
| 调用超时 | 建议改用更小的模型，或缩小单次重构的代码范围 |

## 使用建议

1. **一次只做一件事。** 「重构 + 加功能」应拆成两步，先重构再改功能。
2. **长代码分批处理。** 超过 300 行按函数粒度分批提交，结果更稳定。
3. **应用前先验证。** 重构结果应经过测试或用例验证后再替换到生产代码。
