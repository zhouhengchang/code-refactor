# 支付宝 AI收 接入说明

本文档说明「代码重构助手」如何接入支付宝 **AI收**，实现按调用次数即时收款。

---

## 一、AI收 是什么

AI收 是支付宝面向 AI 服务提供方推出的收款能力。用户调用你的 AI 服务时，可以按次、按量或订阅方式即时完成支付，无需跳转到独立收银台。

对本服务的意义：用户每次调用「代码重构」接口，实时扣费 1 元；前 3 次免费体验。

---

## 二、接入流程（三步）

### 第 1 步：入驻签约

1. 访问 [支付宝开放平台](https://open.alipay.com/) 并登录。
2. 完成**开发者入驻**：
   - 个人开发者：完成实名认证（身份证 + 人脸核身）
   - 企业开发者：提交营业执照与法人信息
3. 在产品中心找到 **AI收**，点击签约。签约时需要填写：
   - 服务名称：代码重构助手
   - 服务类目：开发工具 / 效率工具
   - 计费模式：按次计费（也可选按量或订阅）

> **费率提示**：个人开发者在 **2026 年 12 月 31 日前享受 0 费率优惠**。
> 即每笔收款不扣除手续费，1 元收入即到账 1 元。
> 具体费率与有效期以支付宝开放平台最新公示为准，企业开发者费率另计。

### 第 2 步：创建应用

1. 进入开放平台「[我的应用](https://open.alipay.com/develop/manage)」→ 创建应用。
2. 在应用的能力列表中添加 **AI收**。
3. 配置以下信息：
   - **回调地址**：`https://code-refactor-api.app.workbuddy.host/alipay/notify`（用于接收支付结果通知）
   - **返回地址**：`https://code-refactor-api.app.workbuddy.host/refactor/success`（用户支付完成后跳转）
   - **应用私钥 / 支付宝公钥**：按官方指引生成，**务必保存在环境变量中，不要提交到代码仓库**

4. 提交审核，等待应用上线。

> ⚠️ **安全红线**：`App ID`、`应用私钥`、`支付宝公钥` 一律通过环境变量注入
> （`ALIPAY_APP_ID` / `ALIPAY_PRIVATE_KEY` / `ALIPAY_PUBLIC_KEY`），
> 本项目的所有配置文件中均不含任何真实密钥。

### 第 3 步：安装 SDK

服务端安装支付宝官方 Python SDK：

```bash
pip install alipay-sdk-python
```

初始化（示例，密钥从环境变量读取）：

```python
# -*- coding: utf-8 -*-
"""支付宝 AI收 客户端初始化示例。密钥一律从环境变量读取，不硬编码。"""

import os
from alipay.aop.api.AlipayClientConfig import AlipayClientConfig
from alipay.aop.api.DefaultAlipayClient import DefaultAlipayClient

# 从环境变量读取配置，缺失时直接报错，避免误用空密钥
config = AlipayClientConfig()
config.server_url = "https://openapi.alipay.com/gateway.do"
config.app_id = os.environ["ALIPAY_APP_ID"]
config.app_private_key = os.environ["ALIPAY_PRIVATE_KEY"]
config.alipay_public_key = os.environ["ALIPAY_PUBLIC_KEY"]
config.sign_type = "RSA2"
config.charset = "utf-8"

client = DefaultAlipayClient(alipay_client_config=config)
```

## 三、计费流程

```
用户发起重构请求
      │
      ▼
┌─────────────────┐
│ 校验免费额度     │  剩余额度 > 0 ──► 直接执行重构 ──► 返回结果
└─────────────────┘
      │ 额度用尽
      ▼
┌─────────────────┐
│ 调用 AI收 下单   │  生成 1 元收款订单
└─────────────────┘
      │
      ▼
┌─────────────────┐
│ 用户完成支付     │  支付成功 ──► 执行重构 ──► 返回结果
└─────────────────┘
      │ 支付失败/取消
      ▼
   不执行重构，不计费
```

**关键规则**：

- **先付费后服务**：额度用尽时必须完成支付才执行重构。
- **失败不计费**：重构失败或服务异常时自动退款，不扣用户费用。
- **免费额度**：新用户 3 次免费，用于体验效果。

## 四、计费模式选择建议

| 模式 | 定价 | 适用场景 |
|---|---|---|
| 按次计费 | ¥1.00 / 次 | 推荐起步方案，用户决策成本低 |
| 按量计费 | ¥0.50 / 次（批量） | 包月套餐，如 29 元含 200 次 |
| 订阅制 | ¥29.00 / 月 | 有稳定重构需求的团队开发者 |

**建议**：先以 **0.5 元/次**冷启动，收集 20-50 个用户的实际使用反馈；
确认效果后上调至 1-2 元/次。定价依据是单次调用的 GPU 推理成本 + 平台手续费。
