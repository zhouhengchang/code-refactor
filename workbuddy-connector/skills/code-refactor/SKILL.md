# 代码重构助手

调用 WorkBuddy 连接器 `code-refactor` 提供的 MCP 工具，将遗留代码重构为现代、可维护的规范代码。
所有推理在用户本机的 Ollama 服务上完成，**代码不会上传到任何第三方服务器**。

## 触发条件

当用户表达以下意图时，应主动使用本技能：

| 用户说法 | 说明 |
|---|---|
| 「重构这段代码」「重构一下」 | 通用重构请求 |
| 「优化这个函数」 | 针对单个函数的改进 |
| 「这段代码太乱了」「看着很乱」 | 可读性重构 |
| 「提取重复逻辑」 | 结构重构 |
| 「补充类型标注」「加上类型」 | 类型完善 |
| 「改成现代写法」 | 语法现代化 |
| 「变量名看不懂」 | 命名重构 |

**不适用场景**：纯代码解释（用普通问答即可）、代码审查找 bug（应走审查流程）、单字符改名（直接编辑更快）。

## 工具与参数

### `check_status`

无参数。返回 Ollama 服务与模型状态。

**建议**：首次使用，或用户报告调用失败时，先调用此工具确认环境。

返回示例：

```json
{
  "ok": true,
  "available": true,
  "host": "http://localhost:11434",
  "model": "deepseek-coder",
  "installed_models": ["deepseek-coder:latest"],
  "message": "Ollama 服务正常，模型 deepseek-coder 已就绪。"
}
```

若 `available` 为 `false`，提示用户执行 `ollama pull deepseek-coder`。

### `refactor_code`

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | 是 | 待重构的源代码片段 |
| `task` | string | 是 | 重构任务描述，尽量具体 |
| `language` | string | 否 | 编程语言提示，如 `python`、`javascript`、`java`；不填由模型判断 |

返回示例：

```json
{
  "ok": true,
  "code": "重构后的完整代码",
  "raw": "模型原始输出",
  "model": "deepseek-coder",
  "language": "python",
  "elapsed_ms": 3820
}
```

失败时返回 `{"ok": false, "error": "可读中文错误信息", "error_type": "..."}`。

## 调用流程

1. **确认要重构的代码**。若用户在对话中已给出代码块，直接使用；若只给了文件路径，先读取文件内容。
2. **明确重构任务**。用户描述模糊时（例如只说「优化一下」），先追问一句具体目标，或基于代码特征给出合理任务描述（如「统一命名规范、提取重复逻辑、补充类型标注与文档注释」）。
3. **调用 `refactor_code`**，把语言一并传入以提高准确率。
4. **展示重构结果**，并简要说明关键改动点。

## 安全规则（必须遵守）

1. **结果需用户确认后再替换原代码。** 重构完成后，以代码块形式展示结果并说明改动要点，
   **不得直接写入用户文件**。必须等用户明确表示「应用」「替换」「写入」后，才执行文件修改。
2. **不得擅自扩大改动范围。** 只重构用户指定范围的代码。如发现范围外的问题，另行提示，不擅自修改。
3. **涉及敏感文件时先确认。** 若目标文件包含凭证读取、密钥管理、鉴权逻辑等，
   重构前先提醒用户，由用户决定是否继续。
4. **不要上传代码。** 明确告知用户推理在本机完成。若用户配置了远端 Ollama，也应提示代码会发送到该远端地址。

## 异常处理

| 错误类型 | 表现 | 处理方式 |
|---|---|---|
| `ollama_unreachable` | 无法连接 Ollama | 提示用户启动 Ollama 服务，并检查连接器配置中的 `ollama_host` |
| `model_not_found` | 未找到模型 | 提示用户执行 `ollama pull deepseek-coder` |
| `payload_too_large` | 代码超过 20000 字符 | 建议按函数或模块拆分后分次提交 |
| `empty_response` | 模型返回空内容 | 建议重试，或换用更大的模型 |
| 超时（超过 25 秒） | 模型响应过慢 | 建议改用更小的模型（如 `deepseek-coder:1.3b`），或缩小重构范围 |

## 最佳实践

- **任务描述越具体，结果越好。** 对比：
  - 差：「优化代码」
  - 好：「把这段嵌套 if 改为提前返回，提取重复的校验逻辑为独立函数，并补充中文注释」
- **长代码分而治之。** 超过 300 行的代码建议按函数粒度分批提交。
- **先小范围验证。** 对核心业务逻辑，先重构一个函数确认效果，再批量处理。
