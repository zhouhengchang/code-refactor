# 代码重构助手（code-refactor-pro）

一个按调用付费的代码重构能力。把「能跑但难维护」的代码，改成「好读、好改、行为不变」的代码。

## 能力边界

**能做的**：

- **命名规范化** —— 把 `f`、`a`、`tmp1` 这类名字改为能表达意图的命名
- **重复逻辑提取** —— 识别重复片段，提取为独立函数或方法
- **控制流简化** —— 嵌套条件改为卫语句（提前返回）、合并冗余分支
- **类型标注补充** —— 为 Python、TypeScript 补充类型标注
- **文档注释生成** —— 补充符合语言惯例的文档注释（Python docstring、JSDoc、Javadoc）
- **语法现代化** —— 回调改 async/await、`var` 改 `let/const`、旧式循环改推导式等

**明确不做的**：

- 不改变函数/类的公开签名（除非任务明确要求）
- 不引入新的第三方依赖
- 不做功能新增或行为变更
- 不做类型检查器的替代品（只补标注，不做全量类型推导验证）
- 不做安全审计（不保证发现注入、越权等问题）

## 使用方式

### 调用参数

| 槽位 | 必填 | 说明 |
|---|---|---|
| `code` | 是 | 待重构代码，≤ 20000 字符 |
| `task` | 是 | 重构要求，≤ 500 字符 |
| `language` | 否 | 语言标识，不填自动判断 |

### 标准调用

```json
{
  "code": "def f(a):\n    r = []\n    for i in a:\n        if i % 2 == 0:\n            r.append(i * i)\n    return r\n",
  "task": "函数名和变量名改为有意义的命名，补充类型标注与中文注释，保持行为不变",
  "language": "python"
}
```

### 返回

```json
  "model": "deepseek-coder",

  "elapsed_ms": 3820

```

## 触发规则

**应当触发**（命中以下任一，且 `negative_keywords` 未命中）：

- 用户贴出一段代码，并说「重构」「优化一下」「太乱了」「清理一下」
- 用户明确要求提取重复逻辑、改命名、补类型、加注释
- 用户要求把旧写法换成新语法

**不应触发**：

- 「解释这段代码」→ 直接讲解
- 「这段代码有什么 bug」→ 走审查流程
- 「帮我加一个功能」→ 走功能开发
- 「写测试」→ 走测试生成

触发词刻意收窄为「重构 / 优化实现 / 提取重复逻辑 / 清理遗留代码」等具体表达，避免与平台已有的「代码解释」「代码审查」类技能抢占触发。

## 异常处理

| error_type | 含义 | 建议动作 |
|---|---|---|
| `invalid_argument` | `code` 或 `task` 为空 | 补齐缺失参数后重试，不计费 |
| `payload_too_large` | 代码超过 20000 字符 | 按函数或模块拆分，分次提交 |
| `model_not_found` | 后端模型未就绪 | 服务端问题，稍后重试 |
| `ollama_unreachable` | 推理服务不可达 | 服务端问题，稍后重试 |
| `empty_response` | 模型返回空 | 缩小重构范围后重试 |
| `timeout` | 超过 30 秒 | 缩小代码范围，或改用更小的模型 |

所有异常均返回可读中文信息，不暴露内部堆栈。

## 使用建议

1. **一次一个目标。** 想同时「重构 + 加日志 + 改功能」时，拆成多次调用，结果更可控。
2. **大文件分批。** 单次 ≤ 300 行为宜，按函数粒度提交。
3. **结果先验证再应用。** 重构结果保持逻辑等价是设计目标，但仍建议跑一遍现有测试后再替换。
4. **写清 task。** 「优化一下」不如「把五层嵌套 if 改为提前返回，并提取重复的参数校验」。
